## Documentation Policy

Before implementing a new feature:

1. Document the problem and business purpose.
2. Define the workflow and business rules.
3. Review and approve the design.
4. Build the feature in small milestones.
5. Test each milestone.
6. Update documentation when implementation changes.
7. Commit and push the stable checkpoint.

Documentation is part of the product and must remain synchronized with the code.
